# CDR Analyzer — เว็บแอปวิเคราะห์ข้อมูล CDR

แอปนี้วิเคราะห์ข้อมูลการใช้โทรศัพท์ (Call Detail Record) จากผู้ให้บริการเครือข่ายในไทย และหาความเชื่อมโยงระหว่างหมายเลขเป้าหมายหลายหมายเลข
ใช้งานผ่านเบราว์เซอร์ได้ทันทีโดยไม่ต้องติดตั้ง และ**ประมวลผลทั้งหมดในเครื่องของผู้ใช้** ไฟล์ CDR จะไม่ถูกอัปโหลดไปที่ใด

- ใช้งานออนไลน์ (GitHub Pages): `https://chalee2000.github.io/CDR/` (ใช้ได้หลังเปิด GitHub Pages ตามหัวข้อ [การเปิด GitHub Pages](#การเปิด-github-pages))
- ใช้งานแบบออฟไลน์: แอปถูก build เป็นไฟล์ `dist/index.html` ไฟล์เดียว ดับเบิลคลิกเปิดได้เลย

## วิธีใช้

1. ลากไฟล์ CDR (`.xlsx` หรือ `.csv`) มาวางที่แถบด้านซ้าย จะวางหลายไฟล์ หลายเป้าหมายพร้อมกันก็ได้
   - ถ้าแค่อยากลองใช้ ให้กด **"ใช้ข้อมูลตัวอย่าง (สมมติ)"**
2. ตั้งชื่อเรียกให้แต่ละเป้าหมายได้ (ปุ่ม ✎) เช่น "นาย ก."
3. ดูผลในแต่ละแท็บ
4. คลิกเลขหมายใดก็ได้ เพื่อเปิดไทม์ไลน์การติดต่อทั้งหมดของเลขนั้น (รวมทุกเป้าหมาย)
5. ใส่ข้อมูลบุคคลของเลขหมายได้ (ชื่อ นามสกุล ชื่อเล่น ที่อยู่ ประวัติคดีอาญา หมายเหตุ และรูป)
   - เปิดได้จาก 3 ที่: คลิกเลขในผังเครือข่าย, หน้ารายละเอียดของเลขนั้น หรือปุ่ม 👤 ในรายการเป้าหมาย
   - ชื่อและรูปจะแสดงในผัง ตาราง และไฟล์ Excel
   - ข้อมูลนี้อยู่ในหน้าเว็บเท่านั้น ถ้าจะเก็บไว้ใช้ครั้งหน้า ให้กด **"บันทึกเป็นไฟล์"** ที่ส่วน "ข้อมูลบุคคล" ในแถบซ้าย และครั้งต่อไปกด **"เปิดไฟล์ข้อมูลบุคคล"** (ดู [ความเป็นส่วนตัว](#ความเป็นส่วนตัว))
6. ส่งออกผลได้ 3 แบบ:
   - **ส่งออก Excel**: ได้ไฟล์หลายชีตพร้อมนำไปทำรายงาน
   - **ดาวน์โหลด CSV**: ส่งออกทีละตาราง
   - **พิมพ์ / PDF**: พิมพ์หรือบันทึกหน้าที่เปิดอยู่
7. เก็บงานไว้ทำต่อด้วยเมนู **"สำรอง/กู้ไฟล์"** ที่แถบด้านบน (ดู [สำรองและกู้ไฟล์งาน](#สำรองและกู้ไฟล์งาน))

| แท็บ | เนื้อหา |
| --- | --- |
| ภาพรวม | ช่วงข้อมูล จำนวนโทรออก/เข้า/ไม่สำเร็จ เวลาสนทนา SMS การใช้อินเทอร์เน็ต ผู้ติดต่อ IMEI/IMSI พื้นที่ที่ปรากฏบ่อย คุณภาพข้อมูล และข้อจำกัดของไฟล์ |
| คู่ติดต่อ | อันดับคู่ติดต่อ แยกโทรออก/เข้า/ไม่สำเร็จ เวลาสนทนา SMS จำนวนวัน การติดต่อกลางคืน ครั้งแรก/ล่าสุด และบอกว่าเลขนั้นพบในไฟล์ของเป้าหมายอื่นด้วยหรือไม่ |
| ช่วงเวลา | กราฟรายวัน ปริมาณข้อมูลรายวัน กราฟรายชั่วโมง แผนภาพวัน×ชั่วโมง ช่วงที่ไม่มีรายการ และเวลาเริ่ม/เลิกใช้งานรายวัน |
| Call burst | ช่วงที่ติดต่อถี่ (ตั้งเกณฑ์ได้ เช่น ≥ 5 ครั้งใน 10 นาที นับโทร + SMS หรือเฉพาะการโทร) ของทุกเป้าหมาย: กราฟวัน × เวลาของวัน ตารางช่วงพร้อมคู่ติดต่อ เสา และป้ายกลางคืน รายละเอียดและผังของแต่ละช่วง คู่ติดต่อที่ปรากฏซ้ำในหลายช่วง และช่วงที่หลายเป้าหมายติดต่อถี่พร้อมกัน (Candidate) |
| พื้นที่และการเดินทาง | แผนที่เสา เส้นทางรายวัน เสาที่ใช้บ่อย พื้นที่ที่อาจเป็นที่พัก/ที่ทำงาน (Candidate) และการย้ายพื้นที่ระดับจังหวัด/อำเภอ/เสา |
| อุปกรณ์ | IMEI (เทียบ 14 หลักแรก) IMSI ลำดับการเปลี่ยนเครื่อง เครื่อง 2 ซิม และเครื่องของคู่สายที่ผู้ให้บริการแนบมา |
| ผังเครือข่าย | Link chart แบบผังสืบสวน (สไตล์ i2): ไอคอนตามประเภทเลขหมาย, รูปบุคคล, ลูกศรบอกว่าใครโทรหาใคร และตัวเลขจำนวนครั้งบนเส้น ผู้ติดต่อร่วมอยู่ระหว่างเป้าหมาย มีค้นหาเลขหรือชื่อ ดูเฉพาะเครือข่ายรอบเลข เต็มจอ และบันทึกภาพ PNG คลิกเลขหรือเส้นเพื่อดูรายละเอียด พร้อมตาราง Degree, Betweenness, PageRank, Community (Louvain) และตารางเส้นแยกตามทิศทาง |
| เชื่อมโยงข้ามเป้าหมาย | ผังผู้ติดต่อร่วมและการติดต่อกันโดยตรง ลำดับการติดต่อทอด (A→X→B) อุปกรณ์/ซิมร่วม และการอยู่พื้นที่เดียวกัน |
| รายการข้อมูล | ทุกรายการพร้อมตัวกรอง และอ้างอิงกลับไปที่ชีตและแถวในไฟล์ต้นฉบับได้ |

## รูปแบบไฟล์ที่รองรับ

### AIS แบบตารางเดียว
มีคอลัมน์ `START_DATETIME, END_DATETIME, A_NUMBER, B_NUMBER, RECORD_TYPE (MOC/MTC/SMO/SMT), DURATION, IMSI, IMEI, LAC, CI, TAC, ECI, PLMN, LOCATION_NAME, SITE_NAME, REGION, PROVINCE, AMPHUR, TUMBOL`

- `A_NUMBER` คือเป้าหมาย และตำแหน่งในแถวของเป้าหมายเป็นของเครื่องเป้าหมาย
- **เป้าหมายมี IMSI เดียว** คือ IMSI ที่ใช้มากที่สุด ถ้ามี IMSI อื่นในไฟล์ แถวนั้นเป็นของคู่สาย ทั้งพิกัดและ IMEI (ดู [IMSI เดียวต่อเป้าหมาย](#imsi-เดียวต่อเป้าหมาย-ทุกค่าย))
- ไฟล์ที่มีแถวว่างที่จัดรูปแบบไว้นับล้านแถว (ชีตใหญ่หลายสิบ MB) อ่านได้ตามปกติ
- ไฟล์ไม่มีพิกัด แผนที่จึงวางเสาที่**จุดกลางตำบล**ตามชื่อพื้นที่ในไฟล์ (`PROVINCE`, `AMPHUR`, `TUMBOL`) และระบุชัดว่าเป็น "ตำแหน่งโดยประมาณ"
  - ถ้าไม่พบชื่อตำบล ใช้จุดกลางอำเภอ (กรุงเทพฯ ใช้จุดกลางเขต เพราะข้อมูลต้นทางไม่มีจุดของแขวง) และถ้าไม่พบอีกจึงใช้จุดกลางจังหวัด
  - คอลัมน์ "พิกัด" ในตารางเสาบอกระดับที่ใช้: "≈ ตำบล" / "≈ อำเภอ" / "≈ จังหวัด"
  - หลายเสาในพื้นที่เดียวกันวางห่างกันเล็กน้อยเพื่อไม่ให้ซ้อนกัน
  - จุดกลางเป็นจุดกลางพื้นที่ ไม่ใช่ตำแหน่งเสา
  - ถ้ามีไฟล์พิกัดเสา ให้นำเข้าได้ที่ **การตั้งค่า → พิกัดเสาเพิ่มเติม** เป็น CSV ที่มีคอลัมน์ `ECI` หรือ `CELL_ID` หรือ `SITE_NAME` และ `LAT`, `LON`

### True / DTAC แบบหลายชีต
ประกอบด้วยชีต `Info` และ `VOICE service`, `IMS service`, `SMS service`, `DATA service`, `WIFI Service` และมีพิกัดเสามาให้

- อ่านหมายเลขเป้าหมายจาก `Search by: MSISDN=…` ในชีต Info
- **ไฟล์มีบันทึกจากเครื่องของคู่สายที่อยู่เครือข่ายเดียวกันด้วย** ระบบจึงแยกว่าแต่ละแถวเป็นของใคร
  - ดู IMSI ของเป้าหมายจากชีต DATA ก่อน
  - ถ้าไม่มี IMSI จึงดูจาก role: `MO`/`ORIGINATING_ROLE` เป็นของฝั่ง A และ `MT`/`TERMINATING_ROLE`/`SMS-MT` เป็นของฝั่ง B
  - ถ้าไม่มีชีต DATA จะใช้ IMSI ที่อยู่ฝั่งเป้าหมายมากที่สุด
- **แถว IMS ที่ใช้ IMSI ของเป้าหมายแต่ไม่มี IMEI**
  - ในไฟล์จริง พิกัดของแถวเหล่านี้อยู่คนละพื้นที่กับเป้าหมาย เช่น สายเดียวกันในชีต VOICE ที่มี IMEI อยู่คนละจังหวัด และมักตรงกับพื้นที่ของคู่สาย
  - ระบบจึงไม่นับเป็นตำแหน่งของเป้าหมาย แต่เก็บเป็นตำแหน่งฝั่งคู่สาย และติดหมายเหตุ "จากแถว IMS ไม่มี IMEI"
- **แผนที่**: วงกลม ● คือตำแหน่งของเป้าหมาย สี่เหลี่ยม ■ คือตำแหน่งของคู่สาย (ไม่ใช่ของเป้าหมาย) ซ่อนสี่เหลี่ยมได้ที่ช่องเลือกเหนือแผนที่
- **การโทรครั้งเดียวอาจถูกบันทึกได้ถึง 4 แถว** ได้แก่ ขาของผู้โทรและผู้รับ ซึ่งแต่ละขาอาจอยู่ในชีต IMS (VoLTE) และ/หรือชีต VOICE ระบบรวมแถวเหล่านี้เป็นการโทรครั้งเดียว ดังนี้
  - แถวที่มีหมายเลข A/B เดียวกันและเวลาเริ่มห่างกันไม่เกิน 3 วินาที ถือเป็นสายเดียวกัน (สายที่รับสายแล้วจะตรงกันถึงระดับวินาที และระยะเวลาต่างกันไม่เกิน 1 วินาที)
  - การโทรไม่สำเร็จ: ชีต VOICE บันทึกเวลาช้ากว่าชีต IMS ได้ถึงประมาณ 15 วินาที แถว VOICE ที่ไม่สำเร็จซึ่งตามหลังแถว IMS ที่ไม่สำเร็จของคู่เดียวกันภายใน 20 วินาที จึงนับเป็นครั้งเดียว
  - สองแถวจากชีตเดียวกันและเครื่องเดียวกันจะไม่ถูกรวมกัน (ถือเป็นการโทรคนละครั้ง)
  - รายการที่รวมแล้วแสดงแหล่งเป็น "VOICE + IMS" และอ้างอิงแถวต้นฉบับครบทุกแถวในแท็บ "รายการข้อมูล"
- IMS ที่ไม่มี Duration ถือเป็นการโทรที่ไม่สำเร็จ

### IMSI เดียวต่อเป้าหมาย (ทุกค่าย)
ไฟล์ CDR ของเลขหนึ่งมี IMSI ของเป้าหมายเพียงค่าเดียว

- IMSI ของเป้าหมายคือ IMSI ในชีต DATA (True/DTAC) หรือ IMSI ที่ใช้ในแถวของเป้าหมายมากที่สุด
- **แถวที่มี IMSI อื่นเป็นของคู่สาย** ทั้งพิกัดและ IMEI
  - ไม่นำไปใช้ในแผนที่ (แสดงเป็นสี่เหลี่ยมแทน) เสาที่ใช้บ่อย พื้นที่ที่อาจเป็นที่พัก เส้นทาง หรือรายการเครื่องของเป้าหมาย
  - แสดงแยกในคอลัมน์ "เสาของคู่สาย" และในหน้ารายละเอียดของเลขนั้น
- ตาราง **"ตรวจเจ้าของพิกัดจาก IMSI"** ในแท็บภาพรวม (และชีตเดียวกันใน Excel) บอกทุก IMSI ว่าเป็นของใคร เลขหมายที่ใช้ IMSI นั้น IMEI ที่ใช้ด้วย จำนวนแถวที่มีพิกัด และพิกัดถูกนับเป็นของใคร
- **แก้เจ้าของเองได้** ที่คอลัมน์ "แก้ไขเจ้าของ" ในตารางนี้
  - ตัวเลือกคือ อัตโนมัติ / เป็นของเป้าหมาย / เป็นของคู่สาย
  - แผนที่ เสา เส้นทาง และอุปกรณ์คำนวณใหม่ทันที
  - ค่าที่แก้ติดไปกับไฟล์สำรอง และตาราง/Excel แสดงว่า "กำหนดเอง" พร้อมผลที่ระบบตัดสินเดิม
  - IMSI ของชีต DATA แก้ไม่ได้ เพราะชีตนี้มีเฉพาะการใช้งานของเป้าหมายตามหมายเรียก

### ตารางทั่วไป (.xlsx/.csv)
ระบบจับคู่หัวคอลัมน์ทั้งภาษาไทยและอังกฤษให้อัตโนมัติ เช่น `วันที่`, `เวลา`, `เบอร์ต้นทาง`, `CALLED_NUMBER`, `DURATION`
ถ้าหาคอลัมน์ที่จำเป็นไม่ครบ ระบบจะเปิดหน้าต่างให้เลือกคอลัมน์เอง
CSV อ่านได้ทั้ง UTF-8 และ Windows-874 ส่วนไฟล์ `.xls` รุ่นเก่ายังไม่รองรับ ให้บันทึกเป็น `.xlsx` ก่อน

## ข้อควรระวังในการตีความ

- **เวลาที่ลงท้ายด้วย `Z`**: ไฟล์ AIS เขียนเวลาแบบ `2026-08-01T09:15:30.000Z` แต่รูปแบบการโทร (เช่น แทบไม่มีกิจกรรมช่วงตี 3–6) ชี้ว่าเป็นเวลาไทยอยู่แล้ว
  - ค่าเริ่มต้นจึง**ถือเป็นเวลาไทยตามที่เขียน**
  - ถ้าแน่ใจว่าเป็น UTC จริง ให้เปลี่ยนที่ **การตั้งค่า → เวลาในไฟล์ที่ลงท้ายด้วย "Z"**
  - เวลาที่แสดงไม่ขึ้นกับเขตเวลาของเครื่องที่เปิดดู
- **แถวซ้ำทุกคอลัมน์**: มักเป็น SMS ที่ถูกแบ่งเป็นหลายท่อน ค่าเริ่มต้นนับทุกแถวเพื่อให้ตรงกับไฟล์ต้นฉบับ แต่เปิด "รวมแถวซ้ำ" ได้
- **เลขบริการและชื่อผู้ส่ง** (เช่น `AIS`, `900515`, `KBank`) แยกออกจากเลขหมายบุคคล และไม่รวมในผังเครือข่ายเว้นแต่เลือกเอง
- **เลขต่างประเทศ** ที่มี prefix ของผู้ให้บริการ (เช่น `69710959…` → `+959…` เมียนมา) ถูกรวมเป็นเลขเดียว โดยยังเก็บค่าดิบไว้ดูได้
- **เสาสัญญาณไม่ใช่พิกัด GPS**: การใช้เสาเดียวกันไม่ได้ยืนยันว่าอยู่ด้วยกัน
- **Centrality / Community / ลำดับการติดต่อทอด / Co-location** เป็นข้อสังเกตเชิงโครงสร้างและเชิงเวลา ใช้จัดลำดับสิ่งที่ควรตรวจสอบต่อ ไม่ใช่หลักฐานว่าผู้ใดกระทำผิด

## สำรองและกู้ไฟล์งาน

ข้อมูลทั้งหมดอยู่ในหน้าเว็บเท่านั้น ปิดหน้าแล้วหาย เมนู **"สำรอง/กู้ไฟล์"** ที่แถบด้านบนจึงใช้เก็บงานทั้งหมดเป็นไฟล์เดียว แล้วเปิดกลับมาทำต่อได้ในเครื่องใดก็ได้

- **สำรองไฟล์…** บันทึกเป็น `CDR-backup_YYYYMMDD-HHmm.cdrbak` ซึ่งมี:
  - ไฟล์ CDR ที่นำเข้าทุกไฟล์ (ทุกเซลล์ตามที่อ่านได้) และคอลัมน์ที่เลือกเองสำหรับไฟล์ที่ระบบจับคู่ไม่ได้
  - ชื่อเรียกและสีของแต่ละเป้าหมาย
  - ข้อมูลบุคคลพร้อมรูป
  - พิกัดเสาที่นำเข้า
  - การตั้งค่าการวิเคราะห์ (ไม่รวมธีม และไม่รวมตัวเลือกแผนที่ออนไลน์ ซึ่งคงตามเครื่องที่เปิด)
- **ตั้งรหัสผ่านได้และเป็นค่าเริ่มต้น** (อย่างน้อย 8 ตัวอักษร)
  - ไฟล์ถูกเข้ารหัสด้วย AES-GCM 256 บิต โดยใช้กุญแจจากรหัสผ่านผ่าน PBKDF2-SHA256 600,000 รอบ (Web Crypto ของเบราว์เซอร์)
  - ถ้าไฟล์ถูกแก้ไขหรือเสียหาย จะเปิดไม่ได้
  - **ลืมรหัสผ่านแล้วกู้ไม่ได้** ไม่มีใครเปิดไฟล์ได้อีก
  - ถ้าไม่ตั้งรหัสผ่าน ใครได้ไฟล์ไปก็อ่านได้
- **กู้ไฟล์…** (หรือลากไฟล์ `.cdrbak` มาวางในช่องนำเข้า)
  - แอปถามรหัสผ่าน (ถ้ามี) ตรวจไฟล์ทุกช่อง แล้วแสดงสรุปเป้าหมาย ข้อมูลบุคคล และพิกัดในไฟล์ให้ตรวจก่อน
  - กดยืนยันแล้ว งานในไฟล์สำรอง**จะแทนที่**งานที่เปิดอยู่ทั้งหมด
- ไฟล์สำรองมีข้อมูล CDR และข้อมูลส่วนบุคคล ให้เก็บรักษาตามระเบียบของหน่วยงาน (`.gitignore` กันไฟล์ `.cdrbak` ไว้แล้ว)
- รูปแบบไฟล์ (สำหรับผู้พัฒนา) อยู่ใน `src/lib/backup.ts`:
  - ไฟล์เริ่มด้วย `CDRBAK`
  - ตามด้วย header JSON ที่ไม่มีข้อมูลจากไฟล์ CDR
  - ตามด้วยข้อมูลแบบ NDJSON ที่บีบอัดด้วย gzip และเข้ารหัสเมื่อมีรหัสผ่าน

## ความเป็นส่วนตัว

- ไฟล์ถูกอ่านด้วย JavaScript ในเบราว์เซอร์ ไม่มีเซิร์ฟเวอร์ และไม่มีการส่งข้อมูลออก
- ไม่เก็บข้อมูล CDR ไว้ในเบราว์เซอร์ ปิดหน้าแล้วข้อมูลหายไป สิ่งที่จำไว้มีเพียงค่าการตั้งค่าและธีม
  - งานออกจากเบราว์เซอร์ได้ก็ต่อเมื่อผู้ใช้กดบันทึกไฟล์เอง (ไฟล์ Excel ไฟล์ข้อมูลบุคคล หรือไฟล์สำรอง)
- **ข้อมูลบุคคล** (ชื่อ ที่อยู่ ประวัติคดี รูป) เป็นข้อมูลที่ผู้ใช้กรอกเอง ไม่ได้มาจากไฟล์ CDR
  - เก็บในหน่วยความจำของหน้าเว็บเท่านั้น จะออกจากเบราว์เซอร์ก็ต่อเมื่อผู้ใช้กด "บันทึกเป็นไฟล์" (`CDR-profiles_YYYYMMDD-HHmm.json`) และถ้ายังไม่ได้บันทึก เบราว์เซอร์จะถามก่อนปิดหน้า
  - **ไฟล์นี้มีข้อมูลส่วนบุคคล** ให้เก็บรักษาและส่งต่อตามระเบียบของหน่วยงาน
  - รูปที่ใส่จะถูกย่อเป็น 256×256 และเข้ารหัสใหม่ในเบราว์เซอร์ ข้อมูลแฝงในรูป (EXIF เช่น พิกัด GPS หรือรุ่นกล้อง) จึงไม่ติดไปในไฟล์
  - ไฟล์ที่เปิดเข้ามาถูกตรวจทุกช่อง และรูปถูกเข้ารหัสใหม่ก่อนใช้
- การเชื่อมต่อภายนอกมีเพียงภาพแผนที่ฐานจาก OpenStreetMap ซึ่งผู้ให้บริการแผนที่จะรู้ว่ากำลังเปิดดูพื้นที่ใด
  - ปิดได้ที่ **การตั้งค่า → แผนที่ฐานออนไลน์** แล้วแอปจะใช้เส้นขอบประเทศแบบออฟไลน์แทน
- repository นี้เป็นสาธารณะ **ห้าม commit ไฟล์ CDR จริง** (`.gitignore` กันไฟล์ `.xlsx`/`.csv` ไว้ทุกที่ ยกเว้น `samples/` ซึ่งเป็นข้อมูลสมมติ)

## การพัฒนา

ต้องใช้ Node.js 22 ขึ้นไป

```bash
npm install
npm run dev          # เปิดเซิร์ฟเวอร์สำหรับพัฒนา
npm run typecheck    # ตรวจชนิดข้อมูล TypeScript
npm test             # unit test (vitest)
npm run build        # สร้าง dist/index.html ไฟล์เดียว
npm run e2e          # ทดสอบในเบราว์เซอร์ด้วย Playwright (ต้อง build ก่อน)
npm run make:samples # สร้างไฟล์ตัวอย่างใน samples/ ใหม่
npm run make:gazetteer # สร้างจุดกลางตำบล/อำเภอ (src/assets/th-area-centroids.json) ใหม่จากข้อมูลต้นทาง
```

ตรวจตัวเลขกับไฟล์จริงของตัวเองได้โดยไม่ต้องนำไฟล์เข้ามาใน repository:

```bash
npm run verify:local -- /path/outside/repo/file1.xlsx /path/outside/repo/file2.xlsx
SHOT_DIR=/tmp/shots CDR_REAL_FILES=/path/a.xlsx:/path/b.xlsx npm run e2e
```

โครงสร้างโค้ด:

```
src/lib/parsers/    อ่านรูปแบบ AIS, DTAC และตารางทั่วไป แล้วแปลงเป็น Interaction
src/lib/analysis/   สรุป คู่ติดต่อ ช่วงเวลา พื้นที่ อุปกรณ์ เครือข่าย และความเชื่อมโยงข้ามเป้าหมาย
src/lib/export/     ส่งออก Excel และ CSV
src/lib/samples/    ตัวสร้างข้อมูลสมมติ
src/views/          หน้าจอแต่ละแท็บ
src/components/     ตาราง กราฟ (ECharts) แผนที่ (Leaflet) ผังเครือข่าย และหน้ารายละเอียดเลขหมาย
tests/unit/         unit test
tests/e2e/          ทดสอบในเบราว์เซอร์
```
